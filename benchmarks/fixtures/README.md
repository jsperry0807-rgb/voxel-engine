# Fixture worlds

These are frozen, reproducible saves used by benchmark and gate work. They are
not player saves and they are not produced by the production world generator.

## `m1-representative`

**Status: provisional until the first real save.**

`m1-representative/` is the M1-28 fixture. It exists so M1-35 (memory
distribution) and M1-37 (edit latency) can measure a save with realistic shape
instead of a synthetic pattern generated inside the benchmark process.

| Path | Meaning |
|---|---|
| `m1-representative/manifest.json` | provenance, recipe, format, material-id map, hashes, observations and limitations |
| `m1-representative/save/r.<x>.<y>.<z>.vxr` | the frozen save, exactly as the storage layer wrote it |

The save is 72 chunks (a 6×6×2-chunk box spanning `x,z = -192..191` and
`y = 0..127` at the 64³ edge) in four region files. It contains:

- terrain with sea level, beaches, sandstone subsoil, a snow/ice peak, ocean
  and lake water, dirt/grass soil, and a bedrock floor;
- chambers, tunnels, galleries, vertical shafts and water-filled caves,
  including air below y = 38 that cannot be sky;
- a canyon cut with natural stone roof shelves (overhangs) and an open span;
- a keep, a ruined wall, a bridge with supports, ordinary trees and one
  landmark tree;
- 19 distinct non-air materials: stone, dirt, grass, cobblestone, sand,
  gravel, water, oak log/leaves, bedrock, four ores, tall grass, a flower,
  snow, ice and sandstone.

`checks` in the manifest are measured from the save bytes, not declared by the
generator: cave air below the sky line, overhang roof blocks, cobblestone
structure blocks and tree blocks. `observed` is the M1-27 save-scan report
(chunk/voxel distributions, material histogram, byte totals) with the path
removed so the manifest is checkout-independent.

### Provenance

The bytes are generated by `crates/bench/src/fixture/world.rs` from the recipe
in the manifest: a seed, a chunk box and the built-in material order. They were
written through the real `World` / `RegionStore` path, not hand-assembled.
Generation is integer-hash deterministic; there is no `rand`, clock, float or
platform state in the result.

The manifest records the source commit and whether the worktree outside the
fixture directory was dirty when it was frozen. It is honest provenance for a
synthetic object, not evidence of gameplay.

### Limitation

This fixture is **provisional until the first real save**. It was not produced
by gameplay, by `docs/worldgen-design.md`, or by the save path on the reference
machine. Do not quote its file sizes, material histogram or per-chunk
distributions as gate results. Capture a real save, re-freeze this fixture
against it, and only then treat the numbers as evidence.

The save also has no palette of its own: region records store raw material
ids. The manifest's `palette` is the id-to-key mapping for this frozen file and
is checked against the built-in registration order. A change to that order, or
to `CHUNK_BITS` or the chunk format, makes verification fail rather than
silently reinterpreting the bytes.

### Build and verify

```sh
# Verify hashes, scan the checked-in save, and rebuild it from the recipe.
cargo run -p voxel-bench -- fixture verify

# Measure the per-chunk memory distribution over the frozen save (M1-35).
cargo run -p voxel-bench -- gate memory

# Freeze a new fixture into an empty directory (refuses to overwrite).
cargo run -p voxel-bench -- fixture build --out benchmarks/fixtures/m1-representative

# Verify a manifest elsewhere.
cargo run -p voxel-bench -- fixture verify --manifest path/to/manifest.json
```

`fixture verify` is the contract. It loads the manifest, checks the file set and
sizes, recomputes the BLAKE3 world hash, re-runs the M1-27 scan and the
geometric feature checks, then generates the recipe into a temporary directory
and requires byte-identical files. A fixture that cannot be rebuilt is not
frozen, just committed.

The fixture is built at 64³ chunks. At the pre-registered 128³ edge the
verifier fails with an explicit chunk-edge mismatch; the 64³ bytes are not
valid 128³ data. Re-freeze at the matching edge if a future gate needs it.

### Re-freezing

A freeze is deliberate:

1. remove the old fixture directory;
2. run `fixture build`;
3. run `fixture verify`;
4. commit the new save and manifest together.

When the first real save exists, capture it with the same format, recompute the
manifest fields from that save, and update this page: the status, provenance and
limitations must change in the same commit as the bytes.
