# M2.5-05 macro tile generator

**Status:** landed 2026-11-01. `cargo run -p voxel-worldgen -- macro --seed 1`
generates the whole 1,024 km macro map in seconds and prints a stable content
hash.

## Acceptance

| Requirement | Result |
|---|---|
| Macro tile generator at 128 m | `MacroGenerator::generate_tile(pos)` fills all five channels per cell centre |
| Seeded | one `u64`; the seed alone determines every byte |
| Content-hashed | `MacroTile::content_hash` over the identity header and payload; CLI folds all 4,096 into one world hash |
| 4,096 tiles generate in minutes | **9.2 s** single-threaded, **444 tiles/s** (release, reference machine) |
| Hash stable across runs | two runs print `615d6d05683c34ff` |

Verify with `cargo run -p voxel-worldgen -- macro --seed 1`.

## Fields

| Field | Formula | Range |
|---|---|---|
| continentalness | 2-octave 900 km continent fbm (gain 2.4) + 3-octave 400 km coastline fbm (gain 0.9), per-seed bias, 40 km ocean rim | `[-1, 1]` |
| erosion | 3-octave fbm, 180 km base wavelength | `[0, 1]` |
| surface | `splines::surface_height(c, e)` + 24 km / 8 km valley detail | 0–12,000 m |
| height channel | `height_from_q16(surface)` | 0–48,000 units |
| temperature | `Climate::temperature` | `u8` |
| humidity | `Climate::humidity` with the ocean-distance ramp | `u8` |
| erosion channel | `unit_to_u8(erosion)` | `u8` |

Each cell samples the **centre** of its 128 m square, so neighbouring tiles
agree exactly at a border (the shared border cell belongs to one tile only,
and a 16 km tile covers 125 cells per axis).

### Continents, valleys and the ocean share

A 1,024 km world spans barely one 900 km continent wavelength, so the seed
decides whether the raw field sits above or below zero. A fixed bias gave an
ocean share between 0.345 and 0.70 depending on the seed. The generator
therefore **calibrates per seed**: it samples the raw field on a 64 × 64 grid
at 16 km and biases so the 35th percentile is zero. That is a function of the
seed, not stored data, so tiles still regenerate identically.

The **valley detail** (24 km at 300 m, 8 km at 120 m) is added to the shape
spline and weighted by `RELIEF_WEIGHT`, so it exists only on the land interior:
the ocean floor and beaches stay flat. It is what lets water gather into
rivers instead of running radially off a dome — see
[`m2.5-shape-fix.md`](m2.5-shape-fix.md) for the before/after measurements.

The calibration targets 38% at the 16 km probe grid; the extra three points
compensate for coastline detail that the probe grid misses, so the full 128 m
field measures **35.1%** (22,451,644 sea cells of 64M, seed 1). The world also
has an **ocean rim**: continentalness is capped at `-1` on the border, reaches
zero at 20 km and is uncapped at 40 km, which matches the design's deep ocean
edge and makes every border outlet sea.

`macro_generator_land_fraction_is_about_a_third` checks 0.28–0.42,
`macro_generator_land_is_continent_scale` checks 1–7 landmasses, and
`macro_generator_border_is_ocean` samples the whole frame.

### Ocean distance before hydrology

Humidity needs a distance to the nearest ocean. The real distance is a
hydrology product (M2.5-06/07), which runs after the macro map. Until then the
generator uses a **continentalness ramp**: `distance = max(0, c) × 512 km`.
It is monotone — coasts are wet, interiors dry — and needs no neighbour tile,
so every tile remains a pure function of `(seed, pos)`. M2.5-06 computes the
real hydrology but does not yet write it into tiles; the channel is replaced
when rivers and lakes are stored (M2.5-07/08), which bumps `MACRO_VERSION`.

### Flags

`WATER` at or below sea level (26,400 units), `COAST` in the 16 m band above
it. `RIVER` and `LAKE` stay clear until hydrology; the tile decoder rejects
unknown bits, so adding them is a deliberate format decision.

## Tile header

Every generated tile carries `seed`, `generator_version = 1`,
`macro_version = 1`, `content_version = 1` and its `TilePos`. The CLI and the
decoder agree on all five; `macro_generator_fills_the_header_and_every_channel`
checks them.

## Content hash

```text
content_hash = FNV-1a 64( header bytes 0..36 || payload )
```

The range is exactly the bytes the tile CRC covers, so the hash changes when
the seed, a version, the position or any cell changes. `fnv_start()` and
`fnv_u64()` let a caller fold tile hashes without storing tiles; the CLI does
this in row-major order and prints:

```text
macro seed=1 tiles=4096 bytes=384163840 ms=14566 tiles_per_s=281.2
world_hash=4a7fd7354f810b8f
```

The world hash is stable across runs and machines because the payload is
little-endian and the fields are integer-only. It is not in the tile file; it
is a build artefact for comparing generation runs.

## Command line

```sh
cargo run -p voxel-worldgen -- macro [--seed N] [--limit N] [--out DIR]
```

- `--seed` accepts decimal or `0x` hex (default 1).
- `--limit` generates the first N tiles row-major, for smoke runs.
- `--out` writes `<DIR>/<x>_<z>.vxt`; each file decodes with
  `MacroTile::from_bytes`.

A full run writes 384,163,840 bytes if `--out` is used. Deduplication and a
tiled store are M2.5-09.

## Performance

Reference machine (Ryzen 5 7600), release build, single-threaded:

| Quantity | Value |
|---|---:|
| Per tile | 3.6 ms |
| 4,096 tiles | 14.6 s |
| Throughput | 281 tiles/s |
| World payload | 384.16 MB |

The task's bar is "minutes"; the measured run is well inside it, and worker
parallelism (M2.5-24) is not needed for creation yet. Cost per cell is five
fbm fields (15 noise samples), one spline evaluation and two climate noise
samples; the continent, coastline and two valley streams are the shape fix in
[`m2.5-shape-fix.md`](m2.5-shape-fix.md).

## Later fix

The first field release had a metre/kilometre unit bug that made
continentalness a ~6 m wavelength noise field. The corrected scale, the
continent component, the per-seed calibration and the valley detail are
recorded in [`m2.5-shape-fix.md`](m2.5-shape-fix.md); the numbers above are the
fixed field.
