# M2.5-02 macro grid and 16 km tile

**Status:** landed 2026-11-01. The macro grid model and the tile binary format
are frozen at format version 1.

## Acceptance

| Requirement | Result |
|---|---|
| Macro grid data model | 128 m cells, 8,000 × 8,000 cells, five channels |
| 16 km tile format | 125 × 125 cells, 93,750 B payload, 40 B header |
| Height `u16`, climate/erosion/flags `u8` | channel-major planes, little-endian |
| Header carries seed + versions + CRC | seed `u64`, generator/macro/content `u16`, CRC-32 |
| Tile round-trips | `tile_round_trips_every_field` compares every plane and re-encodes byte-identically |
| `125² × 6 B = 93.75 KB` | asserted in `tile_payload_size_matches_the_design` |
| Corrupt tile rejected | structural cases, CRC cases, reserved flags, wrong length |

Verify with `cargo test -p voxel-worldgen tile` (13 tests).

## Model

| Constant | Value | Derivation |
|---|---:|---|
| `CELL_SIZE_M` | 128 m | design §3.1 |
| `TILE_CELLS` | 125 | 16,000 m / 128 m |
| `TILE_EXTENT_M` | 16,000 m | 128 × 125 |
| `WORLD_CELLS` | 8,000 | 1,024,000 / 128 |
| `TILES_PER_AXIS` | 64 | 8,000 / 125 |
| `TILE_COUNT` | 4,096 | 64² |

Both divisions are exact, so tiles neither overlap nor leave a seam. The tests
sum the tile area over all 4,096 positions and compare it with the world area.

`TilePos` is signed (`i32`) so neighbour lookups can walk one tile past the
edge; only `TilePos::is_inside_world` decides validity, and it is enforced when
a tile is constructed and when one is decoded. `TilePos::containing_cell` and
`local_cell` convert between world cell and tile-local coordinates.

### Channels

| Channel | Type | Unit | Notes |
|---|---|---|---|
| height | `u16` | 0.25 m | 12,000 m peak = 48,000 units; max representable 16,383.75 m |
| temperature | `u8` | 1/255 | 0 coldest, 255 hottest |
| humidity | `u8` | 1/255 | 0 driest, 255 wettest |
| erosion | `u8` | 1/255 | 0 least eroded, 255 most |
| flags | `u8` | bit field | `RIVER` 0, `LAKE` 1, `COAST` 2, `WATER` 3 |

Sea level 6,600 m is exactly 26,400 units, so a coastline never suffers from
storage rounding. Height conversions are integer millimetres, not floats:
`height_mm`, `height_from_mm` (round half up, saturating) and
`height_from_metres` (multiplies in `u64` so even `u32::MAX` metres saturates
instead of overflowing).

The four high flag bits are reserved: the decoder rejects a tile that sets one
(`TileError::UnknownFlags`), so a new flag needs a format-version bump rather
than a silent reinterpretation of existing data.

## File layout

| Offset | Bytes | Field |
|---:|---:|---|
| 0 | 4 | magic `VXTL` |
| 4 | 2 | format version `1` |
| 6 | 2 | reserved, zero |
| 8 | 8 | seed |
| 16 | 2 | generator version |
| 18 | 2 | macro version |
| 20 | 2 | content version |
| 22 | 2 | reserved, zero |
| 24 | 4 | tile x (`i32`) |
| 28 | 4 | tile z (`i32`) |
| 32 | 4 | cell count, 15,625 |
| 36 | 4 | CRC-32 over bytes 0–35 and the payload |
| 40 | 93,750 | payload |

The payload stores the height plane as 15,625 `u16`, then 15,625 bytes each of
temperature, humidity, erosion and flags. One tile file is **93,790 bytes**;
the whole world is **4,096 × 93,790 = 384,163,840 B (384.16 MB)**, matching the
design's 384 MB raw estimate.

### Why channel-major

Height is the hot channel: the far-field mesh, the 2D map and every chunk's
surface lookup read heights in long runs, and a contiguous `u16` plane gives
32 heights per cache line. Climate and flags are read cell by cell, where a
separate byte plane costs nothing. The in-memory layout is the on-disk layout,
so encoding is one copy per channel with no per-cell branch.

### Why the CRC is covered the way it is

The CRC covers the header up to its own field, then the payload. A corrupt
identity byte (seed, version, position) therefore fails the checksum even
though it is not structurally invalid, while the structural fields that a
decoder must trust early (magic, format, reserved words, cell count) are
checked first so their errors stay precise.

CRC-32/ISO-HDLC now lives in `voxel-core::checksum` with an incremental
`Crc32`. The storage region log re-exports it from
`voxel_storage::hash::crc32`, so both on-disk formats share one polynomial
implementation. The tile needs the incremental form because the header and
payload are not adjacent: the CRC field sits between them.

## Validation order

1. exact length (`Length`)
2. magic (`Magic`)
3. format version (`Format`)
4. reserved header words (`Reserved`)
5. cell count (`CellCount`)
6. tile position (`TilePosition`)
7. CRC (`Checksum`)
8. flag bits (`UnknownFlags`)

Tests cover every branch, including a payload bit flip, a seed edit that only
the CRC can catch, a CRC-valid tile at tile column 64, and a CRC-valid tile
with reserved flag bits.

## Measurements

Reference machine (Ryzen 5 7600), release build, 2,000 round trips of a
fully populated tile:

| Operation | Per tile | Throughput |
|---|---:|---:|
| `to_bytes` | 144 µs | 650 MB/s |
| `from_bytes` | 155 µs | 604 MB/s |

A full-world encode is about 0.6 s and a decode about 0.65 s, so tile I/O is
not the constraint on the minutes-long creation pass. This is orientation, not
a gate; M2.5-05 owns the generation throughput target.

## Version policy

- The **format version** is `1`. The decoder rejects every other value, so a
  future layout change is explicit.
- The **generator**, **macro** and **content** versions are stored but not
  interpreted yet. M2.5-25 pins them in the save header and decides which old
  generator remains callable.
- A reserved flag bit is treated as corruption, not as forward compatibility.
