# M2.5-04 climate fields

**Status:** landed 2026-11-01. Latitude, ocean distance and the altitude lapse
are frozen; the macro tile's temperature and humidity channels are now
defined.

## Acceptance

| Requirement | Result |
|---|---|
| Compressed latitude, cold edges and warm equator | `LATITUDE_WARMTH`, 8 knots from `z = 512 km`, symmetric about the equator |
| Humidity from ocean distance | `OCEAN_HUMIDITY`, 6 knots from 0 to 512 km, non-increasing |
| Altitude lapse rate | `ALTITUDE_LAPSE`, 0 at sea level, 0.80 at the 12,000 m peak |
| Poles cold | pole lowland ≤ 20/255, equator ≥ 240/255 |
| Coasts humid | coast ≥ 220/255, 512 km inland ≤ 90/255 |
| Peaks cold | equatorial peak ≤ 80/255, at least 150 levels below lowland |
| 2D map test | 33 × 17 temperature map and an 8 × 513 humidity map, both monotone |

Verify with `cargo test -p voxel-worldgen climate` (15 integration tests, 3
unit tests).

## Inputs

| Input | Type | Source |
|---|---|---|
| `x`, `z` | Q16.16 metres | world position (M2.5-05) |
| `surface` | Q16.16 metres | `splines::surface_height` |
| `ocean_distance` | Q16.16 metres | distance to the nearest ocean cell, from the continentalness field (M2.5-05); refined by hydrology in M2.5-06 |

The climate is a pure function of `(seed, x, z, surface, ocean_distance)`. It
owns two noise streams for the variation term and nothing else.

## Formulas

```text
temperature = unit_to_u8( latitude_warmth(z)
                        - altitude_lapse(surface)
                        + temperature_noise(x, z) )

humidity    = unit_to_u8( ocean_humidity(ocean_distance)
                        + humidity_noise(x, z) )
```

`unit_to_u8` clamps to `[0, ONE]` and rounds half up: sea-level equator → 255,
a pole → 0.

### Latitude

The world is 1,024,000 m pole to pole and stands in for a hemisphere, so the
climate zones are ~10× compressed (design §1). The equator is at
`z = 512,000 m`; the polar distance is `|z - equator| / 512,000`.

| Polar distance | Warmth |
|---:|---:|
| 0.00 | 1.00 |
| 0.15 | 0.98 |
| 0.30 | 0.92 |
| 0.45 | 0.80 |
| 0.60 | 0.62 |
| 0.75 | 0.42 |
| 0.90 | 0.18 |
| 1.00 | 0.00 |

The curve approximates `cos` without `libm`, is symmetric by construction, and
is a monotone PCHIP table, so it cannot overshoot into a cold patch at the
equator or a warm patch at a pole.

### Altitude

| Surface | Temperature loss |
|---|---:|
| 6,600 m (sea level) | 0.00 |
| 9,300 m | 0.38 |
| 12,000 m (peak) | 0.80 |

Below sea level the table clamps at its first knot, so the ocean floor is the
temperature of the water surface, not of its depth. This is the design's
"universal rock-to-snow above the treeline": an equatorial peak lands at 0.20
of the channel, cold enough for M2.5-12 to treat it as snow regardless of the
biome below.

### Ocean distance

| Distance | Humidity |
|---:|---:|
| 0 km (coast) | 0.95 |
| 10 km | 0.85 |
| 30 km | 0.70 |
| 80 km | 0.50 |
| 200 km | 0.32 |
| 512 km | 0.20 |

The table is in Q16.16 **kilometres** because Q16.16 metres beyond 32 km does
not fit the spline's `i32` input. The conversion is one division of the
Q16.16 metre distance by 1,000. Distances beyond the world are clamped.

### Variation

Both channels add an 8 km-wavelength noise term of `±0.06` of the channel
range, seeded from the world seed with distinct salts. Without it, latitude
and coast bands would read as perfect contours; the term is small enough that
every property below still holds (the tests assert the noise-free base and
then check the stored channel against the `±0.06` envelope).

## Profile

Release build, seed 1, `x = 600 km`, sampled every 128 km of latitude:

| Latitude | Lowland | Peak | Humidity at 5 km | At 200 km |
|---:|---:|---:|---:|---:|
| 0 km (pole) | 0 | 0 | 231 | 84 |
| 128 km | 107 | 0 | 224 | 77 |
| 256 km | 190 | 0 | 231 | 84 |
| 384 km | 244 | 40 | 235 | 87 |
| **512 km (equator)** | **255** | **55** | 222 | 75 |
| 640 km | 243 | 39 | 232 | 84 |
| 768 km | 194 | 0 | 222 | 74 |
| 896 km | 108 | 0 | 236 | 89 |
| 1,024 km (pole) | 4 | 0 | 226 | 78 |

The residual values at the poles come from the variation term around a zero
base, and are inside the asserted `≤ 20` bound.

## Interface

```rust
use voxel_worldgen::climate::Climate;

let climate = Climate::new(seed);
let sample = climate.sample(x_m, z_m, surface, ocean_distance_m);
// sample.temperature, sample.humidity: u8 (0..=255)
```

`temperature_base(z, surface)` and `humidity_base(distance)` return the
noise-free Q16.16 values; map renders and the monotonicity tests use them
directly. `latitude_warmth(z)` and `unit_to_u8(value)` are public for the same
reason.

## Measurements

Reference machine (Ryzen 5 7600), release build, 1 M `sample` calls (two noise
lookups, three table lookups, two conversions):

| Operation | Throughput | Per call |
|---|---:|---:|
| `Climate::sample` | 26.2 M/s | 38.2 ns |

Two channels per macro cell; a tile is 15,625 cells, so a full tile of climate
is about 1.2 ms. M2.5-05 owns the combined tile-generation measurement.

## Tests

- Table monotonicity with 129 samples per segment
- Exact equator/pole warmth and symmetry about the equator
- Poles cold, equator hot, peaks cold at every latitude
- Altitude only cools; the ocean floor matches sea level
- Coasts wetter than interiors; humidity falls off monotonically
- Stored channel stays inside the `±0.06` noise envelope
- 2D temperature map (33 × 17) monotone in latitude and altitude
- 2D humidity map (8 × 513) monotone from the coast
- Determinism and seed dependence
- `sample` agrees with the two channel methods
