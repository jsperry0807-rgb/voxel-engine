# M2.5-11 biome RON

**Status:** landed 2026-11-01. The 18 biome definitions are content in
`data/biomes.ron`; code parses and validates them, and the weight function
reads its centres from the file.

## Acceptance

| Requirement | Result |
|---|---|
| RON schema and 18 definitions | `crates/engine/worldgen/data/biomes.ron`: 11 land, 3 ocean, 3 underground, geothermal |
| All definitions validate | `BiomeCatalog::parse` checks count, classes, keys, ranges, unit values, soil depth and flora density |
| Every climate cell resolves | a 7,650-sample sweep over the axes always has a dominant biome with weight ≥ 1/18; every biome is dominant somewhere |
| Every material key resolves in the manifest | surface, flora and ecotone keys are checked against `blocks.ron` through `BlockRegistry::id_of` |
| Content is data-only | the catalogue is `include_str!`-ed, parsed at runtime; an edited centre changes the weights without a code change |

Verify with `cargo test -p voxel-worldgen biome_ron` (13 tests).

## Schema

The file matches the design's §7 shape, plus the weight centre:

```ron
(
    key: "voxel:forest",
    class: Land,
    centre: (continentalness: 0.62, temperature: 0.50, humidity: 0.70, erosion: 0.35, depth: 0.0),
    climate: (temperature: (0.35, 0.70), humidity: (0.50, 0.90), erosion: (0.20, 0.60)),
    surface: (top: "voxel:grass_block", filler: "voxel:dirt", stone: "voxel:stone", beach: "voxel:sand"),
    soil_depth: (3, 6),
    flora: [
        (species: "voxel:oak_log", density: 0.08),
        (species: "voxel:fern", density: 0.20),
    ],
    ecotone: ["voxel:birch_log"],
    structures: ["ruins", "towers"],
    map_color: (72, 110, 58),
    fog: (0.55, 0.62, 0.58),
)
```

| Field | Meaning |
|---|---|
| `key` | stable namespaced identity, also the weight-table label |
| `class` | `Land`, `Ocean`, `Underground` or `Rare` |
| `centre` | softmax centre, five axes in `[0, 1]` |
| `climate` | temperature, humidity and erosion envelope |
| `surface` | top, filler, stone and beach material keys |
| `soil_depth` | default soil thickness range, 1–8 blocks |
| `flora` | species key and per-block density |
| `ecotone` | species that live only on the border (birch, dead bush) |
| `structures` | prefab names; M2.5-19 owns the prefabs |
| `map_color` | the far-field/map colour (M2.5-30) |
| `fog` | per-biome fog tint in `[0, 1]` |

## The 18

| Class | Biomes |
|---|---|
| Land | beach, plains, forest, taiga, swamp, hills, mountains, alpine, desert, savanna, tundra |
| Ocean | shelf, deep, trench |
| Underground | aquifer, fungal_deep, cavern |
| Rare | geothermal |

Surface palettes use only keys already in `blocks.ron`, including the M2.5-30/31
faces: `dry_grass_block`, `savanna_grass_block`, `taiga_grass_block`,
`swamp_grass_block`, `swamp_mud`, `red_sand`, `alpine_rock`, `tundra_moss`,
`deep_ocean_floor`, `clay`, `deep_stone`, `fungal_cap`, `fungal_stem`,
`geothermal_rock`, `obsidian`. The palette table doubles as M2.5-30's
acceptance list: it names the top/filler/stone/beach key of every biome and
freezes `map_color`.

## Validation

`BiomeCatalog::parse` (structure):

- exactly 18 entries, 11/3/3/1 by class;
- unique namespaced keys;
- every climate range and fog component in `[0, 1]`, low ≤ high;
- every centre axis in `[0, 1]`;
- soil depth `1 ≤ low ≤ high ≤ 8`;
- flora density in `[0, 1]`.

`BiomeCatalog::validate(resolve)` (content): every surface material, flora
species and ecotone key must resolve. The test passes
`|key| registry.id_of(key).is_some()` with the committed `blocks.ron` and
`materials.gen.ron`, so a palette that names a missing block fails the suite.

## Weight integration

The weight function no longer carries a code table. `crate::biomes::catalog()`
parses the embedded file once; `centres_q16()` converts the centres to Q16.16
(rounding at parse time, not per sample). `BiomeWeights::at(axes)` uses the
embedded centres, and `at_with(axes, &centres)` takes any catalogue — that is
how the data-only test proves an edited file changes the result.

The iterated weights between 18 biomes are unchanged: the M2.5-10 acceptance
(348 m transition, exact sum, no argmax switch) still passes against the RON
centres.

## Tests

- Catalogue shape: count, class counts, unique keys, soil and density ranges.
- Every material/flora/ecotone key resolves in the block manifest.
- Unknown key reporting names both the biome and the key.
- Every climate cell resolves: exact sums, a dominant biome everywhere, and
  every biome dominant somewhere (including the depth sweep that reaches
  `aquifer`).
- Centres in the catalogue equal the weight input.
- Rejections: short file, duplicate key, bad key, inverted range, out-of-range
  unit, bad soil depth, bad density, wrong class count, broken RON.
- Data-only: an edited RON changes the parsed centre and the weight vector.
- Lookup and `is_empty`.
