# M2.5-09 macro tile store

**Status:** landed 2026-11-01. Tiles stream through an LRU cache and sample
seamlessly across tile borders.

## Acceptance

| Requirement | Result |
|---|---|
| Tiled streaming | `TileSource` loads one tile on demand; `DirectorySource` reads `macro --out` files |
| LRU | 2-slot eviction test: the least recently used tile is dropped |
| 3 × 3 border for interpolation | `load_view` warms the 3 × 3 neighbourhood; sampling reads each corner from its owning tile |
| 32 km view holds ≤ 9 tiles | 9 tiles, 843,750 B of payload (under the design's 1 MB) |
| No seams at tile borders | a midpoint sample that needs one cell from each tile equals the analytic bilinear value |
| Verify | `cargo test -p voxel-worldgen tile_store` (12 tests) |

## Design

### Sources

```rust
pub trait TileSource {
    fn load(&mut self, pos: TilePos) -> Result<MacroTile, TileError>;
}
```

`DirectorySource` reads `<dir>/<x>_<z>.vxt`, the layout `macro --out` writes,
and maps a missing file to `TileError::Io`. Tests use an in-memory source that
counts loads, which is how the eviction and view tests can tell a hit from a
miss.

### Cache

`TileStore::new` holds `VIEW_TILES = 9`; `with_capacity` allows other sizes.
Every access bumps a monotonic clock; a miss loads and, if the cache is full,
evicts the entry with the smallest clock. The capacity is deliberately small,
so a linear scan for the victim is cheaper than a linked list and cannot get
out of order.

`resident_bytes()` counts payload bytes only (93,750 per tile). A full view is
843,750 B, under the design's 1 MB; allocator and header overhead are outside
that number but still small.

### Sampling

Cell values sit at cell centres. A Q16.16 world position becomes a fractional
cell coordinate `x / 128 m − 0.5`, split into an index and a Q16.16 fraction.
The four corners are fetched by **world cell coordinate** — each through
`TilePos::containing_cell` — then interpolated:

```text
top    = lerp(v00, v10, tx)
bottom = lerp(v01, v11, tx)
value  = lerp(top, bottom, tz)
```

Everything is Q16.16 integer; heights are converted from 0.25 m units to
metres by shifting two bits.

| Channel | Sample unit |
|---|---|
| `Height` | Q16.16 metres |
| `Temperature`, `Humidity`, `Erosion` | Q16.16 channel value (0–255) |

Positions outside the world clamp to the boundary cells, so an edge sample
never asks for a 64 × 64 tile position that does not exist.

### Why there is no seam

A per-tile sampler that interpolated inside one tile and clamped at its edge
would flatten the last half-cell and then jump when the next tile loads. This
store never treats a tile as the coordinate frame: it asks for cell `(x, z)`
and `(x+1, z)` by their global position. The two may live in different tiles,
and the interpolation is identical to the one a single global grid would give.
The test samples exactly at the border midpoint — half of cell 124 (tile 0) and
half of cell 125 (tile 1) — and requires the exact average, not a tolerance.

## Tests

- LRU eviction and hit counting.
- A 3 × 3 view loads 9 tiles once and then none.
- A 32 km cross-sample touches at most 9 tiles and stays under 1 MB.
- Seam-free border sampling, exact at cell centres and at the midpoint.
- All four channels, including a linear interpolation halfway between cells.
- World-edge clamping and negative coordinates.
- Source errors are reported, not cached, and do not poison the cache.
- `DirectorySource` round trip against a written `.vxt`, plus a missing-file
  error.
- `tile_at` matches `TilePos::containing_cell` across a tile border and clamps
  negative coordinates.
- A corner view loads only the in-world quadrant.
